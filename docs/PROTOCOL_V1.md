# StrongCrypt V1 Protocol Specification

**Status:** DRAFT (freezes after SC-T02 Agent 03 review)  
**Version:** 1  
**Date:** 2026-10-01

This document defines the canonical V1 binary envelope format and public API contract for StrongCrypt. Once frozen, wire-format semantics and reviewed public API shapes require human approval to change.

---

## 1. V1 Cryptographic Profile

- **AEAD primitive:** AES-256-GCM
- **Key size:** 32 bytes (256 bits)
- **Nonce size:** 12 bytes (96 bits)
- **Authentication tag:** 16 bytes (128 bits)
- **Nonce generation:** `RandomNumberGenerator` (cryptographically secure); caller-controlled nonces not exposed in normal API
- **Associated data:** supported
- **Platform primitive:** .NET `AesGcm` with explicit 16-byte tag size constructor

V1 does not expose AES-CBC, AES-ECB, raw CTR, DES/3DES/RC4, unauthenticated encryption, custom ciphers, or configurable tag/nonce/mode parameters in the normal public API.

### Nonce uniqueness and key lifetime

Random 96-bit nonces do not make a key safe for unlimited encryptions. Keys have a finite operational lifetime. Deployments with very high per-key encryption volume require an explicit key-usage policy. V1 does not implement automated usage counters.

## 2. V1 Envelope Binary Format

All multi-byte integers are **little-endian**. Fields appear in strict order. No padding bytes between fields.

### Byte layout

| Offset | Size (bytes) | Field                | Type     | Description                                                                 |
|--------|--------------|----------------------|----------|-----------------------------------------------------------------------------|
| 0      | 2            | Magic                | `u16`    | Fixed value `0x5343` (ASCII "SC")                                          |
| 2      | 1            | Version              | `u8`     | Protocol version; V1 = `0x01`                                              |
| 3      | 1            | Profile              | `u8`     | Algorithm profile; V1 AES-256-GCM = `0x01`                                 |
| 4      | 1            | Flags                | `u8`     | Reserved; must be `0x00` in V1                                             |
| 5      | 1            | KeyIdLen             | `u8`     | Key identifier length (0–64)                                               |
| 6      | KeyIdLen     | KeyId                | `byte[]` | Key identifier bytes (non-secret, application-defined)                      |
| 6+K    | 12           | Nonce                | `byte[]` | 96-bit nonce                                                                |
| 18+K   | 4            | CiphertextLen        | `u32`    | Ciphertext byte count (≤ 2³¹ - 1 for V1)                                   |
| 22+K   | CiphertextLen| Ciphertext           | `byte[]` | AES-GCM ciphertext                                                          |
| 22+K+C | 16           | Tag                  | `byte[]` | 128-bit GCM authentication tag                                              |

**Total envelope size:** `22 + KeyIdLen + CiphertextLen + 16` bytes.

### Field constraints

- **Magic:** must be exactly `0x5343`. Other values rejected.
- **Version:** must be `0x01` for V1. V1 decryption fails closed on any other version.
- **Profile:** must be `0x01` (AES-256-GCM) for V1. Other values rejected.
- **Flags:** must be `0x00` in V1. Any set bit rejected (forward compatibility reserve).
- **KeyIdLen:** 0–64. Values > 64 rejected.
- **KeyId:** arbitrary bytes; non-secret; application controls semantics; length = KeyIdLen.
- **Nonce:** 12 bytes generated by encryption library using `RandomNumberGenerator`.
- **CiphertextLen:** 0 ≤ CiphertextLen ≤ 2,147,483,647 (2³¹ - 1). Larger values rejected to prevent allocation overflow.
- **Ciphertext:** plaintext encrypted by AES-256-GCM.
- **Tag:** 16-byte GCM tag authenticating the ciphertext and AAD.

### Authenticated regions

The GCM authentication tag covers:

1. **Protocol header (22 + KeyIdLen bytes):** Magic through Ciphertext (excluding the tag itself). This binds version, profile, flags, key identifier, nonce, and ciphertext length into the authenticated envelope.
2. **External AAD (if provided):** framed as described in §3.

The entire protocol header is authenticated so that version, profile, flags, and key identifier cannot be tampered with to cause misinterpretation or key confusion.

## 3. External Associated Data (AAD) Framing

When the caller provides external AAD, it is passed to `AesGcm.Encrypt`/`Decrypt` in a **protocol-authenticated frame** to prevent concatenation ambiguity.

### AAD construction

```
AuthenticatedData = ProtocolHeader || ExternalAAD
```

Where:
- **ProtocolHeader** = bytes [0, 22+KeyIdLen) of the envelope (Magic through Ciphertext length field).
- **ExternalAAD** = caller-supplied AAD bytes (may be empty).

The protocol header is always authenticated. If the caller provides no external AAD, `AuthenticatedData = ProtocolHeader` alone.

### Rationale

Binding the protocol header into AAD ensures:
- Version/profile/flags/KeyId cannot be mutated without detection.
- External AAD concatenation is unambiguous (protocol-defined header always precedes external data).
- Decryption can validate envelope structure before attempting cryptographic operations.

## 4. Parsing and Validation Rules

### 4.1 Minimum envelope size

Minimum valid envelope (KeyIdLen=0, CiphertextLen=0):
```
22 + 0 + 0 + 16 = 38 bytes
```

Any buffer < 38 bytes is rejected as truncated before field access.

### 4.2 Parse order (decryption package)

1. **Length check:** reject if buffer.Length < 38.
2. **Magic:** read bytes [0,2); reject if not `0x5343`.
3. **Version:** read byte [2]; reject if not `0x01`.
4. **Profile:** read byte [3]; reject if not `0x01`.
5. **Flags:** read byte [4]; reject if not `0x00`.
6. **KeyIdLen:** read byte [5]; reject if > 64.
7. **Envelope minimum for this KeyIdLen:** reject if buffer.Length < (22 + KeyIdLen + 16).
8. **KeyId:** read bytes [6, 6+KeyIdLen).
9. **Nonce:** read bytes [6+KeyIdLen, 18+KeyIdLen).
10. **CiphertextLen:** read little-endian u32 at [18+KeyIdLen]; reject if > 2,147,483,647.
11. **Final envelope size check:** reject if buffer.Length != (22 + KeyIdLen + CiphertextLen + 16). No trailing bytes allowed in V1.
12. **Ciphertext:** read bytes [22+KeyIdLen, 22+KeyIdLen+CiphertextLen).
13. **Tag:** read bytes [22+KeyIdLen+CiphertextLen, 22+KeyIdLen+CiphertextLen+16).

All validation occurs **before** key resolution and AEAD decryption.

### 4.3 Rejection conditions (format errors, not authentication errors)

Return a distinct **format/protocol error** (not authentication failure) when:
- Magic != `0x5343`
- Version != `0x01`
- Profile != `0x01`
- Flags != `0x00`
- KeyIdLen > 64
- CiphertextLen > 2,147,483,647
- Buffer length inconsistent with declared lengths (truncation or trailing bytes)

These are **structural validation failures** detectable before cryptographic operations.

### 4.4 Authentication failure semantics

Return a **generic authentication failure** (with no distinguishing detail) when:
- `AesGcm.Decrypt` fails (wrong key, modified ciphertext, modified tag, modified AAD, modified nonce).

Authentication failures must not distinguish:
- Wrong key vs. modified ciphertext.
- Modified tag vs. modified AAD.
- Which byte or field caused the failure.

Rationale: avoid oracle attacks that leak key/ciphertext validity through error timing or message detail.

## 5. Public API Contract

### 5.1 Package separation

Three packages with strict capability boundaries:

- **StrongCrypt.Protocol:** wire-format constants, version identifiers, immutable non-secret protocol metadata. No encryption, decryption, key operations, or hostile-input parsing.
- **StrongCrypt.Encryption:** owns encryption and canonical envelope writing. No decryption capability. No reference to `StrongCrypt.Decryption`.
- **StrongCrypt.Decryption:** owns parsing and decryption of hostile envelopes. No encryption capability. No reference to `StrongCrypt.Encryption`.

### 5.2 Encryption API (initial draft)

```csharp
namespace StrongCrypt.Encryption;

/// <summary>
/// Encrypts plaintext using AES-256-GCM and produces a canonical V1 envelope.
/// </summary>
public sealed class AesGcmEncryptor
{
    /// <summary>
    /// Encrypt plaintext with the specified key and optional metadata.
    /// </summary>
    /// <param name="plaintext">Data to encrypt (zero-copy span).</param>
    /// <param name="key">32-byte AES-256 key.</param>
    /// <param name="keyId">Key identifier (0-64 bytes, non-secret, application-defined).</param>
    /// <param name="associatedData">Optional AAD (authenticated but not encrypted).</param>
    /// <returns>Complete V1 envelope as byte array.</returns>
    /// <exception cref="ArgumentException">Invalid key size or keyId length.</exception>
    /// <exception cref="CryptographicException">Encryption failure.</exception>
    public static byte[] Encrypt(
        ReadOnlySpan<byte> plaintext,
        ReadOnlySpan<byte> key,
        ReadOnlySpan<byte> keyId = default,
        ReadOnlySpan<byte> associatedData = default);

    /// <summary>
    /// Encrypt plaintext into a caller-provided destination buffer.
    /// </summary>
    /// <param name="plaintext">Data to encrypt.</param>
    /// <param name="destination">Buffer to receive envelope; must have sufficient capacity.</param>
    /// <param name="key">32-byte AES-256 key.</param>
    /// <param name="keyId">Key identifier (0-64 bytes).</param>
    /// <param name="associatedData">Optional AAD.</param>
    /// <param name="bytesWritten">Number of envelope bytes written.</param>
    /// <returns>True if successful; false if destination too small.</returns>
    public static bool TryEncrypt(
        ReadOnlySpan<byte> plaintext,
        Span<byte> destination,
        ReadOnlySpan<byte> key,
        ReadOnlySpan<byte> keyId,
        ReadOnlySpan<byte> associatedData,
        out int bytesWritten);

    /// <summary>
    /// Calculate required destination buffer size for an envelope.
    /// </summary>
    /// <param name="plaintextLength">Plaintext byte count.</param>
    /// <param name="keyIdLength">Key identifier byte count (0-64).</param>
    /// <returns>Envelope size in bytes.</returns>
    public static int GetEnvelopeSize(int plaintextLength, int keyIdLength);
}
```

**Key validation (encryption):**
- `key.Length != 32` → `ArgumentException`
- `keyId.Length > 64` → `ArgumentException`

**Nonce generation:** internal, using `RandomNumberGenerator`.

**Zeroization:** encryption package zeros any owned temporary plaintext or key buffers when ownership is clear and doing so materially reduces exposure.

### 5.3 Decryption API (initial draft)

```csharp
namespace StrongCrypt.Decryption;

/// <summary>
/// Decrypts V1 envelopes after hostile-input validation.
/// </summary>
public sealed class AesGcmDecryptor
{
    /// <summary>
    /// Decrypt a V1 envelope.
    /// </summary>
    /// <param name="envelope">Complete envelope bytes (hostile input).</param>
    /// <param name="key">32-byte AES-256 key (resolved by caller using envelope KeyId).</param>
    /// <param name="associatedData">Optional AAD (must match encryption AAD).</param>
    /// <returns>Decrypted plaintext.</returns>
    /// <exception cref="FormatException">Invalid envelope structure (magic/version/profile/flags/lengths).</exception>
    /// <exception cref="ArgumentException">Invalid key size.</exception>
    /// <exception cref="CryptographicException">Authentication failure (generic, no detail).</exception>
    public static byte[] Decrypt(
        ReadOnlySpan<byte> envelope,
        ReadOnlySpan<byte> key,
        ReadOnlySpan<byte> associatedData = default);

    /// <summary>
    /// Decrypt into a caller-provided destination buffer.
    /// </summary>
    /// <param name="envelope">Complete envelope bytes.</param>
    /// <param name="destination">Buffer to receive plaintext; must have sufficient capacity.</param>
    /// <param name="key">32-byte AES-256 key.</param>
    /// <param name="associatedData">Optional AAD.</param>
    /// <param name="bytesWritten">Plaintext byte count.</param>
    /// <returns>True if successful; false if destination too small.</returns>
    /// <exception cref="FormatException">Invalid envelope structure.</exception>
    /// <exception cref="ArgumentException">Invalid key size.</exception>
    /// <exception cref="CryptographicException">Authentication failure.</exception>
    public static bool TryDecrypt(
        ReadOnlySpan<byte> envelope,
        Span<byte> destination,
        ReadOnlySpan<byte> key,
        ReadOnlySpan<byte> associatedData,
        out int bytesWritten);

    /// <summary>
    /// Parse envelope to extract key identifier without decrypting.
    /// </summary>
    /// <param name="envelope">Complete envelope bytes.</param>
    /// <returns>Key identifier bytes (may be empty).</returns>
    /// <exception cref="FormatException">Invalid envelope structure.</exception>
    public static ReadOnlyMemory<byte> GetKeyId(ReadOnlySpan<byte> envelope);

    /// <summary>
    /// Calculate plaintext size from a validated envelope.
    /// </summary>
    /// <param name="envelope">Complete envelope bytes.</param>
    /// <returns>Plaintext byte count.</returns>
    /// <exception cref="FormatException">Invalid envelope structure.</exception>
    public static int GetPlaintextSize(ReadOnlySpan<byte> envelope);
}
```

**Key validation (decryption):**
- `key.Length != 32` → `ArgumentException`

**Parsing:** all structural validation (magic/version/profile/flags/lengths) occurs before key resolution or AEAD operations.

**Error semantics:**
- `FormatException`: structural/protocol violations (detectable pre-decryption).
- `CryptographicException`: authentication failure (generic message, no detail).

**Zeroization:** decryption package zeros any owned temporary plaintext or key buffers when ownership is clear and doing so materially reduces exposure.

## 6. Buffer Sizing and Allocation Safety

### 6.1 Envelope size calculation (encryption)

```
EnvelopeSize = 22 + KeyIdLen + PlaintextLen + 16
```

Overflow check: reject if `PlaintextLen > (int.MaxValue - 38 - KeyIdLen)`.

### 6.2 Plaintext size calculation (decryption)

After parsing CiphertextLen from envelope:
```
PlaintextSize = CiphertextLen
```

(GCM plaintext and ciphertext are same length.)

Caller uses `GetPlaintextSize()` to allocate destination buffer before calling `TryDecrypt()`.

### 6.3 Allocation limits

- **CiphertextLen:** capped at 2,147,483,647 (int.MaxValue) in V1 to prevent allocation overflow on 32-bit length fields.
- **KeyIdLen:** capped at 64 to bound header parsing cost and prevent abuse.

Decryption validates lengths before allocation. If `CiphertextLen` would cause allocation failure or overflow, parsing rejects the envelope as malformed.

### 7.2 Hostile-input test cases

Decryption must reject:
- Truncated envelopes (every structural offset).
- Trailing bytes.
- Wrong magic.
- Unsupported version/profile.
- Set reserved flag bits.
- KeyIdLen > 64.
- CiphertextLen > int.MaxValue.
- Modified tag/ciphertext/AAD (authentication failure, generic error).

## 8. Security Considerations

### 8.1 Nonce reuse

Reusing a (key, nonce) pair catastrophically breaks GCM security. V1 mitigates this by generating nonces from `RandomNumberGenerator`. Collision probability for 96-bit random nonces is negligible under reasonable key lifetimes (birthday bound ~2⁴⁸ encryptions).

Deployments with extremely high per-key encryption volume must implement key rotation policies. V1 does not enforce automated limits.

### 8.2 Key identifier is not authenticated by application

The protocol authenticates the KeyId field (it is part of the GCM AAD), but V1 does not validate that the KeyId semantically matches the key provided by the caller. Applications must ensure correct key resolution.

### 8.3 External AAD concatenation

The protocol-authenticated header prevents AAD concatenation ambiguity. An attacker cannot craft two (AAD₁, AAD₂) pairs that hash to the same GCM authentication input by manipulating the boundary.

### 8.4 Timing side channels

GCM tag verification in `AesGcm.Decrypt` is constant-time in .NET. Generic authentication failure prevents oracle attacks that distinguish failure causes.

### 8.5 No unauthenticated plaintext release

Decryption returns plaintext only after `AesGcm.Decrypt` succeeds. Partial plaintext is never exposed on authentication failure.
